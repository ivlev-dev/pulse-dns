# UPDATE подписанной зоны (100k)

Замер: `cargo bench -p pulsed --bench update_signed` (release,
Ryzen 5 3500U, loopback, `durability = flush`).

Сценарий: зона из 100 000 `A` + apex SOA/NS, KSK+ZSK (Ed25519), сервер
подписывает её при старте (NSEC или NSEC3 opt-out), затем каждый UPDATE
добавляет `A` нового имени и удаляет `A` предыдущего (2 RRset).
После каждого UPDATE инкрементально обновляются `RRSIG`, `NSEC`/`NSEC3`
и `SOA` в одной транзакции writer'а.

| denial | n | p50 | p95 | p99 | max |
|---|---:|---:|---:|---:|---:|
| NSEC | 200 | 9.9 ms | 28.6 ms | 36.9 ms | 39.8 ms |
| NSEC3 | 200 | 24.2 ms | 32.4 ms | 44.7 ms | 57.1 ms |

Серия замеров на загруженной машине даёт p99 в диапазоне ~27–45 мс;
цель ≤ 50 мс по p99 выполнена. Отдельные выбросы `max` зависят от
`fdatasync` и не входят в критерий.

`transfer.enabled = false` в bench: при включённом AXFR/IXFR-out
`after_commit` дополнительно материализует снапшот зоны для истории IXFR
(существующая O(zone) стоимость, не относящаяся к DNSSEC-переподписи).

Состав стоимости UPDATE подписанной зоны:

- `O(1)`/`O(depth)` чтений узлов для затронутых имён;
- `O(log n)` поиск соседей в in-memory индексе NSEC/NSEC3
  (полная переподпись и обход зоны отсутствуют; индекс строится при
  полной подписи и обновляется после commit);
- 2–4 подписи Ed25519 (SOA, изменённые RRset, NSEC/NSEC3);
- commit `pulse-zonefile` (доминирует при `flush`).

`O(zone)` остаётся только при холодном индексе (первый UPDATE после
внешней записи), смене SOA TTL/`MINIMUM` и появлении/снятии zone cut.
