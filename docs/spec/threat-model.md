# Модель угроз pulse-dns

- **Статус:** Proposed (требует утверждения Оркестратором/пользователем)
- **Область:** v1 — два бинарника: `pulsed` (авторитативный DNS-сервер, UDP/TCP, primary/secondary, REST CRUD) и `pulseresolved` (рекурсивный резолвер, кеш, ad-block, overrides), DNSSEC sign+validate, REST API управления, AXFR/IXFR/NOTIFY, единый mmap-файл зон с инкрементальными правками. Рекурсия по умолчанию закрыта (только доверенные сети/ACL).
- **Вне области v1:** DNS rebinding protection (известное ограничение, RR-7), DNSCrypt (M5, после отдельного ADR), квантово-устойчивые алгоритмы, multi-tenant SaaS-развёртывание, межхостовый кластер с консенсусом.
- **Связанные документы:** [ADR-0004 «Модель безопасности»](../adr/0004-security-model.md), [Инвентарь криптографии](crypto-inventory.md).

Документ отвечает на вопросы: **что защищаем**, **от кого**, **где проходят границы доверия**, **какие сценарии злоупотреблений реалистичны**, **какие меры обязательны** и **как проверить, что мера внедрена**.

## 1. Соглашения и методология

### 1.1. Идентификаторы

| Префикс | Сущность | Где определён |
|---|---|---|
| `A-*` | актив | раздел 2 |
| `T-*` | нарушитель (threat actor) | раздел 3 |
| `B-*` | граница доверия | раздел 4 |
| `S-*` | сценарий злоупотребления | раздел 6 |
| `R-*` | риск в реестре | раздел 7 |
| `SEC-*` | требование безопасности | ADR-0004 |

### 1.2. Оценка риска

Вероятность `L` и ущерб `I` — целые 1–5. Оценка `R = L × I`.

| Диапазон | Уровень | Реакция |
|---|---|---|
| 1–4 | Low | принимается, мониторинг |
| 5–9 | Medium | устраняется до релиза milestone |
| 10–14 | High | блокирует milestone без меры или явного остаточного риска |
| 15–25 | Critical | блокирует любой релиз; мера обязательна |

Шкалы:
- **L:** 1 — требует редкого стечения условий; 2 — маловероятно; 3 — возможно при целенаправленной атаке; 4 — ожидаемо; 5 — происходит постоянно (сканеры, боты).
- **I:** 1 — незаметно; 2 — локальный сбой; 3 — деградация/искажение одной зоны; 4 — компрометация данных/ключей или простой сервиса; 5 — RCE, утечка ключей, poisoning многих клиентов, репутационный ущерб.

### 1.3. Проверяемость мер

Каждое требование в ADR-0004 имеет метку проверки:

| Метка | Значение |
|---|---|
| `V:unit` | юнит-тест (включая KAT/негативные кейсы) |
| `V:prop` | property-based тест (`proptest`) |
| `V:fuzz` | цель `cargo-fuzz` с бюджетом прогонов |
| `V:integ` | интеграционный тест (реальные сокеты/файлы/пиры) |
| `V:lint` | линт/атрибут компилятора (`#![deny(...)]`, clippy) |
| `V:ci` | гейт CI (`cargo-audit`, `cargo-deny`, санитайзеры) |
| `V:cfg` | валидация конфигурации при старте |
| `V:bench` | перф-гейт (подтверждение компромисса) |
| `V:miri` | прогон под Miri |
| `V:manual` | ручной аудит (минимизируется) |

Формулировки вида «должно быть безопасно» запрещены: требование без метки проверки не принимается.

## 3. Модель нарушителя

| ID | Нарушитель | Исходный доступ | Возможности | Типичная мотивация |
|---|---|---|---|---|
| T-1 | Удалённый аноним | Сеть, UDP/TCP к :53 | Произвольные пакеты, спуфинг src (off-path), amplification, сканирование | DDoS, poisoning, разведка |
| T-2 | Аутентифицированный оператор с ограниченными правами | Валидный токен со scopes | Правка разрешённых зон/конфига, чтение | Ошибка, инсайд, эскалация привилегий, SSRF |
| T-3 | Скомпрометированный пир | TSIG-ключ или mTLS-сертификат secondary/primary | Push/pull зон, NOTIFY, отравление данных | Искажение данных, exfiltration, каскадный poisoning |
| T-4 | Локальный непривилегированный пользователь хоста | Shell под чужой учёткой | Чтение файлов по правам, сигналы/`ptrace` при слабой изоляции | Кража ключей, DoS, подмена файла |
| T-5 | Вредоносный/повреждённый файл зоны или фид blocklist | Запись в файл/поставка фида | Произвольные байты на входе парсера | RCE/UB, порча данных, DoS |
| T-6 | On-path сетевой атакующий | Позиция на маршруте | Инъекция/модификация/дроп DNS-пакетов, фрагментация | Спуфинг, poisoning, downgrade |
| T-7 | Вредоносный upstream | Контроль авторитативного сервера | Произвольные ответы, огромные RRset, приватные адреса, петли | Poisoning, rebinding, DoS, слежка |
| T-8 | Supply-chain атакующий | Публикация/сборка зависимости или артефакта | Вредоносный код в зависимости/сборке | RCE, бэкдор |
| T-9 | **Скомпрометированный/багованный писатель** (параллельный режим) | Право записи в общий файл зон (легитимный процесс с ошибкой или подменённым модулем) | Запись любых страниц, публикация произвольных корней, завышение `high_water`, пометка чужих живых страниц свободными, вечный пин эпохи | Порча данных, DoS, обход изоляции зон |
| T-10 | **Планировщик/ОС/сбой лидера** (параллельный режим) | Задержка потока, OOM, смерть лидера group commit, «уснувший» между пином и валидацией поток | Два лидера, два recovery, потеря пина, ложный таймаут | Порча управляющих структур, двойная аллокация |

**Допущение:** T-1 и T-7 действуют одновременно (off-path + malicious authoritative) — это худший реалистичный случай для резолвера.

  clients           │                                             │
                    │                                             │
  T-2 REST ─────────┤ B2  HTTP :8080 / UDS   pulse-api            │
  operators         │                                             │
                    │                                             │
  T-3 Replication ──┤ B3  AXFR/IXFR/NOTIFY   pulse-server          │
  peers             │                                             │
                    │            pulse-runtime (io_uring)          │
  T-7 Upstreams ────┤ B5  resolver egress                         │
                    │                                             │
  T-4 Local user ───┤ B4  mmap zone file (0600)                   │
  T-5 Zone/feed ────┤ B6  blocklist feeds                         │
                    └─────────────────────────────────────────────┘
                    ┌─────────────────────────────────────────────┐
  T-8 Supply chain ─┤ B8  crates.io / build / artifacts           │
                    └─────────────────────────────────────────────┘

| ID | Граница | Доверенная сторона | Недоверенная сторона | Что пересекает |
|---|---|---|---|---|
| B-1 | DNS-клиенты ↔ сервер | pulse-server | интернет-клиенты | DNS wire (UDP/TCP) |
| B-2 | REST-клиенты ↔ API | pulse-api | операторы/интеграции | HTTP/JSON, токены |
| B-3 | Репликация | pulse-server | пиры | AXFR/IXFR/NOTIFY, TSIG, mTLS |
| B-4 | mmap-файл ↔ процесс | процесс | локальная ФС/данные | байты файла, offsets |
| B-5 | Резолвер ↔ upstream | pulse-resolver | авторитативные серверы | DNS wire |
| B-6 | Blocklist-фиды ↔ процесс | процесс | внешние источники | списки доменов/IP |
| B-7 | Хост/локальный пользователь ↔ процесс | процесс | ОС, другие пользователи | ФС, сигналы, права |

| B-9 | Писатель ↔ писатель (разделяемый файл зон, параллельный режим) | набор доверенных писателей одного uid | другой писатель с той же записью в файл (T-9), сбойный лидер (T-10) | управляющие структуры: `ALLOC_RECORD`, root-история, free pools, epoch-счётчики, writer registry |

| EoP | Побег из «своей зоны» | Багованный/злонамеренный писатель пишет чужие страницы | Аварийная защита `max_page_id`/`fsck`/квоты; от злонамеренного — **не защищает** (RR-9), нужны per-zone файлы/процессы (отдельный ADR) | SEC-PW-006, SEC-PW-009 |

## 6. Сценарии злоупотреблений

### S-01. DNS amplification / reflection
- **Вектор:** T-1 спуфит src IP жертвы, шлёт запросы с большим ответом (ANY, DNSSEC-подписанные, большие TXT) на открытый резолвер/авторитативный сервер.
- **Ущерб:** DDoS жертвы, попадание IP в blocklist (A-9), репутационный ущерб.
- **Меры:** закрытая рекурсия по умолчанию; RRL per source-subnet; DNS Cookies; ANY-минимизация; лимит размера ответа; TC вместо раздувания.
- **Req:** SEC-DNS-006, SEC-DNS-009, SEC-RES-012.

### S-02. Cache poisoning (Kaminsky / birthday / SAD DNS)
- **Вектор:** T-1+T-7. Перебор TXID/порта, инъекция в окно, ICMP side-channel (SAD DNS, CVE-2020-25705), отравление через фрагменты.
- **Ущерб:** искажение ответов множеству клиентов (A-6), фишинг, перехват.
- **Меры:** CSPRNG для TXID+порта на каждый запрос; уникальные tuple; строгий матчинг (addr/port/ID/question); bailiwick; DNSSEC-валидация как основной барьер; 0x20 (опционально); не кешировать out-of-bailiwick; flush при провале валидации.
- **Req:** SEC-RES-001..005, SEC-RES-008.

### S-03. Kaminsky-подобная атака на делегирование
- **Вектор:** Массовые запросы к случайным поддоменам атакуемой зоны, пока резолвер ждёт ответа от авторитативного сервера; попытка подменить NS/glue.
- **Ущерб:** перехват целой зоны.
- **Меры:** строгий bailiwick (glue не авторитетен вне зоны), лимит параллельных subqueries, DNSSEC, randomized source port.
- **Req:** SEC-RES-004, SEC-RES-009.

### S-04. Fragmentation / fragment overlap
- **Вектор:** Форсирование фрагментации больших UDP-ответов; перекрывающиеся фрагменты для обхода stateless-фильтров; FragmentSmack-подобная нагрузка на ядро.
- **Ущерб:** инъекция, DoS ядра.
- **Меры:** EDNS buffer 1232 (избегать фрагментации), предпочтение TCP при TC, лимит размера, актуальное ядро.
- **Req:** SEC-DNS-001, SEC-RES-012.

### S-05. DNS rebinding
- **Вектор:** T-7 возвращает A-записи с приватными/loopback/link-local адресами; клиентское ПО (браузер/агент) обращается к внутренним сервисам.
- **Ущерб:** доступ к внутренней сети через доверенный резолвер.
- **Меры:** **вне v1 — известное ограничение.** Политика отказа приватных ответов не реализуется; риск принимается как остаточный (RR-7). Обязательно: предупреждение в конфиг/лог при рекурсии на интерфейсе, доступном из недоверенной сети, и пункт в документации. При появлении — отдельный ADR.
- **Req:** SEC-RES-010 (deferred).

### S-06. Zone transfer abuse
- **Вектор:** T-1/T-3 инициирует AXFR для exfiltration или нагрузки.
- **Ущерб:** утечка зоны (A-1), DoS primary.
- **Меры:** AXFR/IXFR только ACL+TSIG; нет AXFR по UDP; rate limit; size/time limits; аудит.
- **Req:** SEC-REP-001, SEC-REP-004, SEC-API-007.

### S-07. Slowloris (TCP)
- **Вектор:** Много TCP-соединений с медленной отправкой length-prefix/тела; исчерпание fd/памяти.
- **Ущерб:** отказ в обслуживании TCP-клиентов (A-8).
- **Меры:** лимиты соединений global/per-IP, read/idle timeout, лимит pipelining, max queries/conn.
- **Req:** SEC-DNS-008.

### S-08. REST brute force / credential stuffing
- **Вектор:** T-1/T-2 перебирает токены или пароли.
- **Ущерб:** захват управления (A-5).
- **Меры:** 256-bit токены (перебор неосуществим), rate limit per IP/token, backoff/lockout, аудит неудач.
- **Req:** SEC-API-002, SEC-API-004, SEC-API-007.

### S-09. SSRF через forward-зоны / upstream URL
- **Вектор:** T-2 с правом правки конфига задаёт форвардер/blocklist URL на `127.0.0.1`, `169.254.169.254` (metadata), внутренние сервисы.
- **Ущерб:** доступ к внутренней инфраструктуре, утечка credentials.
- **Меры:** валидация схемы и разрешённых адресов, denylist loopback/link-local/metadata/RFC1918 (если не разрешено явно), запрет редиректов на disallowed, egress-политика.
- **Req:** SEC-API-010.

### S-10. DoS через huge RRset / oversized response
- **Вектор:** T-7 отдаёт RRset на миллионы записей или ответ, раздувающий память.
- **Ущерб:** OOM/CPU, деградация (A-8).
- **Меры:** лимиты количества записей/RRset, бюджеты парсинга, bounded allocation, отказ с SERVFAIL.
- **Req:** SEC-DNS-003, SEC-RES-006.

### S-11. DoS через декомпрессию имён / pointer loops
- **Вектор:** Цепочки compression pointers с петлёй или экспоненциальным разворачиванием (класс SIGRed, CVE-2020-1350; glibc CVE-2015-7547).
- **Ущерб:** CPU/стек, RCE при небезопасном парсере.
- **Меры:** строго назад-указатели, лимит цепочки, лимит 255 октетов, bounds checks, safe Rust, fuzz.
- **Req:** SEC-DNS-002, SEC-DNS-004, SEC-ZF-006.

### S-12. KeyTrap / DNSSEC validation DoS
- **Вектор:** T-7 отдаёт ответ с огромным числом DNSKEY/RRSIG, провоцируя комбинаторную проверку (CVE-2023-50387).
- **Ущерб:** CPU-истощение резолвера.
- **Меры:** лимит DNSKEY/RRSIG на RRset, бюджет криптоопераций на ответ, таймаут валидации, NSEC3 iterations = 0.
- **Req:** SEC-RES-006, SEC-CR-002.

### S-13. NXNSAttack (delegation explosion)
- **Вектор:** T-7 возвращает делегирование на множество NS, заставляя резолвер генерировать лавину запросов.
- **Ущерб:** amplification к third-party и DoS резолвера.
- **Меры:** лимит NS/glue, лимит concurrent subqueries, depth limit, rate limit egress.
- **Req:** SEC-RES-009.

### S-14. Вредоносный/повреждённый файл зон
- **Вектор:** T-5/T-4 поставляет файл с overflow offsets, огромными счётчиками, битыми checksums, усечённый файл.
- **Ущерб:** RCE/UB, порча данных, SIGBUS, отказ старта.
- **Меры:** self-describing header, checked math, bounds checks, page checksums, bounded counts, fail-closed, fuzz, Miri.
- **Req:** SEC-ZF-001..006, SEC-ZF-011..013.

### S-15. Подмена/усечение mmap-файла на лету
- **Вектор:** T-4 делает `truncate`/`rename`/symlink-swap работающего файла.
- **Ущерб:** SIGBUS, чтение чужих данных, порча.
- **Меры:** `flock`, `O_NOFOLLOW`, `fstat`-проверка owner/mode/dev/ino, 0600/0700, async-signal-safe обработчик SIGBUS с аварийным выходом.
- **Req:** SEC-ZF-009, SEC-ZF-010.

### S-16. Компрометация пира репликации
- **Вектор:** T-3 с валидным TSIG/mTLS пушит отравленную зону или тянет данные.
- **Ущерб:** каскадный poisoning secondary, exfiltration.
- **Меры:** валидация переданной зоны (формат, serial, DNSSEC), карантин при провале, ротация TSIG, mTLS, аудит.
- **Req:** SEC-REP-003, SEC-REP-005, SEC-CR-008.

### S-17. Кража DNSSEC-ключей
- **Вектор:** T-4/T-2 читает файлы ключей, дампы, логи, выгружает через API.
- **Ущерб:** подделка ответов зоны (A-3), потеря доверия.
- **Меры:** отдельный каталог 0700, файлы 0600, ключ только в памяти, zeroize при выгрузке, `mlock`, запрет plaintext-экспорта, отдельный scope+mTLS+аудит. HSM — не в v1 (roadmap).
- **Req:** SEC-CR-003, SEC-API-013, SEC-OPS-006.

### S-18. Подделка Idempotency-Key / replay
- **Вектор:** T-2 повторяет ключ идемпотентности с другим телом или в другом tenant.
- **Ущерб:** неверные изменения, обход проверок, путаница состояния.
- **Меры:** ключ привязан к token+method+path+body-hash; конфликт → 409; TTL; изоляция по tenant.
- **Req:** SEC-API-008.

### S-19. Подмена/отравление blocklist-фида
- **Вектор:** T-8/T-7 подменяет фид (HTTP без TLS / редирект на чужой хост) или поставляет огромный/битый список.
- **Ущерб:** ложные блокировки/пропуски, DoS.
- **Меры:** только `https` + allowlist хостов, запрет cross-host редиректов, лимит 64 MiB, timeout, валидация, карантин, аудит. Подпись фида — roadmap (не v1).
- **Req:** SEC-API-010, SEC-API-005.

### S-20. Supply-chain компрометация
- **Вектор:** T-8 публикует вредоносную версию зависимости или подменяет артефакт сборки.
- **Ущерб:** RCE/бэкдор (A-12).
- **Меры:** lockfile, `cargo-audit`/`cargo-deny`, review новых крейтов, reproducible builds, подпись артефактов, SBOM.
- **Req:** SEC-SC-001..007.

### S-21. Параллельная запись: гонка публикации / чтение будущего (T-9, T-10)
- **Вектор:** Писатель A публикует корень зоны `z` версии `T+1`, пока читатель B держит снапшот `T`; либо частично записанный root-слот принимается за валидный; либо пин читателя публикуется после того, как писатель уже решил перезаписать слот.
- **Ущерб:** Читатель видит состояние, которого не было в его снапшоте (нарушение snapshot isolation), либо читает страницы, уже выданные другой зоне (use-after-reuse) → неверные DNS-ответы, тихая порча без CRC-сигнала.
- **Меры:** `RootEntry` ring (4 версии × 2 копии, A/B в разных 4 KiB страницах), `page_limit_at_commit ≤ DP`, пин по формуле `e0`/`e2`/`c1==c2`/`root2.version` с `fence(SeqCst)`, `zone_write_epoch`-RAII, глобальный монотонный `txn`, `owner_zone` в заголовке.
- **Req:** SEC-PW-001, SEC-PW-002, SEC-PW-006, SEC-PW-007, SEC-PW-012, SEC-PW-014.

### S-22. Параллельная запись: двойная аллокация / двойное освобождение (T-9, T-10)
- **Вектор:** Краш между резервированием страниц и публикацией корня оставляет watermark выше durable-лимита или ниже; free-запись публикуется раньше, чем durable корень, выбросивший страницу; donation опережает durable удаление зоны; `txn` переиспользован после рестарта.
- **Ущерб:** Одна страница выдана двум зонам/двум местам графа → перезапись живых данных, порча без явного сигнала (CRC может сойтись).
- **Меры:** `ALLOC_RECORD` A/B (копии в разных страницах) с монотонными `page_limit`/`txn_limit`; курсор в памяти + барьер аллокаций до `CommitRequest`; порядок «данные+ALLOC_RECORD → fsync → корни → fsync»; per-zone buckets + `free_head` в `RootEntry`; «durable drop → free publish»; donation после `free_epoch < D_z`; recovery `max(...)` и `reserve_cursor := DP`; глобальный `txn`.
- **Req:** SEC-PW-003, SEC-PW-004, SEC-PW-005, SEC-PW-008, SEC-PW-010, SEC-PW-012.

### S-23. Параллельная запись: застрявший читатель блокирует запись (T-9, T-10)
- **Вектор:** Живой поток забыл `ZoneSnapshot` (или намеренно держит пин) → `reclaim_version(z)` стоит, зона растёт; все 4 версии ring `≥ MP(z)` → коммит уходит в **chain** (блокировки записи нет); при `EPOCH`-пине широкого батча рекламация заморожена во всех затронутых зонах; при исчерпании `next_page` — `MapFull`.
- **Ущерб:** Отказ в записи в конкретную зону (retryable), как следствие — невозможность применить зону/репликацию; при отсутствии chain — отказ уже после 3 коммитов (долгий AXFR); при chain — рост файла и стоимости чтения. Дополнительно: застрявший `zone_write_epoch` делает зону нечитаемой до восстановления.
- **Меры:** ring 4 версии + **chain обязателен** (коммит не блокируется; `MAX_ROOT_CHAIN_HOPS=4096`); per-zone `ZONE`-пины и короткоживущий `EPOCH`-пин; `zone_write_epoch`-RAII + `ZoneDegraded` за ≤ 8 попыток; метрики `pw_root_chain_depth`/`pw_chain_pages`/`pw_zone_degraded_total`/`pw_stuck_reader_seconds`; живой читатель не вытесняется (SEC-ZF-007), лечение — оператором.
- **Req:** SEC-PW-002, SEC-PW-007, SEC-PW-013.

## 8. Обязательные меры (сводка)

Меры детализированы в [ADR-0004](../adr/0004-security-model.md). Обязательный минимум до любого публичного развёртывания:

1. **Закрытая рекурсия** по умолчанию + RRL + DNS Cookies (R-01).
2. **DNSSEC-валидация** включена для рекурсивного режима; без неё рекурсивный режим считается небезопасным (R-02).
3. **CSPRNG** для TXID/портов/токенов; строгий матчинг ответов (R-02).
4. **Fail-closed mmap**: bounds checks, checksums, отказ старта на повреждённом файле (R-03/R-04).
5. **Ключи DNSSEC** — отдельный каталог 0700, файлы 0600, ключ только в памяти, zeroize при выгрузке, аудит операций, без plaintext-экспорта (R-05).
6. **REST bind localhost** по умолчанию; TLS вне loopback; 256-bit токены с хешем; rate limit 100 rps/token (R-06/R-07).
7. **SSRF-denylist** для forward-зон/upstream; blocklist — только `https` + allowlist хостов, 64 MiB, без cross-host редиректов (R-07/R-20).
8. **AXFR/IXFR/NOTIFY** — только ACL+TSIG (R-08/R-13).
9. **Лимиты протокола**: имя/метка/размер/записи/цепочки/соединения (R-10..R-12, R-21).
10. **Supply chain**: `cargo-audit`/`cargo-deny`, lockfile, review (R-16).
11. **0x20** в резолвере включена по умолчанию, отключаемая настройкой (R-02).
12. **Приватность:** client IP и qname не логируются по умолчанию, только агрегированные метрики (A-13).
13. **Параллельная запись (ADR-0006):** два fsync в group commit (данные+`ALLOC_RECORD` → fsync → корни → fsync), курсор в памяти + `ALLOC_RECORD` A/B (копии в разных страницах), per-zone `RootEntry` ring 4×2 (A/B в разных страницах), глобальный `txn` в `PageHeader.txn` + `owner_zone`, per-zone buckets + donation, пин `e0`/`e2`/`c1==c2`/`root2` + `fence(SeqCst)` + RAII-guard, file-fatal vs zone-fatal, `LOCK_EX`/один recovery, chain как safety valve (T-1), `snapshot_seq` не ceiling + `freeze()` (T-2), RAII-guard + `ZoneDegraded` (T-3), bucket в фазе 1 (T-4), file-fatal (T-5), page 3 (T-6), лимиты/метрики `pw_*`; инварианты `PW-I1..PW-I14` — гейт merge (SEC-PW-001..015). M1 принимается по C-1…C-10 + T-1…T-8; блокер — только M3 (F-5).

## 9. Остаточные риски и допущения

| ID | Остаточный риск | Почему принимаем | Компенсация |
|---|---|---|---|
| RR-1 | On-path атакующий может дропать/задерживать пакеты | Сеть вне контроля | DNSSEC, мониторинг, TCP fallback |
| RR-2 | Zero-day в ядре (io_uring/фрагментация) | Вне периметра приложения | Регулярные обновления, sandbox, минимальные capabilities |
| RR-3 | Скомпрометированный root хоста | Вне модели | Изоляция, аудит, шифрование бэкапов |
| RR-4 | 0x20 ломается на части middlebox | Нестандартный приём | Включена по умолчанию, отключается per-upstream, авто-отключение |
| RR-6 | TSIG HMAC-MD5 в legacy-окружении | Совместимость | Per-key флаг `allow_legacy_hmac_md5` (default off), warning + метрика, deprecated, удаление в v1.1 |
| RR-7 | DNS rebinding не блокируется | Вне v1 (продуктовое решение) | Warning в конфиг/лог при рекурсии на недоверенном интерфейсе, пункт в документации; при появлении — отдельный ADR |
| RR-8 | **Нет межзонной атомарности** (параллельный режим) | Публикация per-zone; глобальная точка публикации = глобальная сериализация, ради устранения которой вводится параллельность. Ни один сценарий v1 не требует согласованного среза нескольких зон | `Snapshot` — набор per-zone версий; multi-zone операции — отдельными коммитами с идемпотентным повтором; запрет полагаться на атомарность в API/docs (SEC-PW-011, PW-L1) |
| RR-9 | **Изоляция зон — не security-граница**: багованный/скомпрометированный писатель (T-9) может писать чужие страницы | Один файл + один uid; внутри файла нет MMU-границы между зонами | Аварийная защита `max_page_id`/`fsck`/квоты/lease; от злонамеренного — только per-zone файлы/процессы (отдельный ADR), R-26 принят как Low |

**Допущения:**
- Процесс — единственный писатель mmap-файла; внешние писатели исключены правами и `flock`.
  - **Базовый режим:** один писатель на файл (`flock(LOCK_EX)`), внешние писатели исключены правами.
  - **Параллельный режим (ADR-0006), v2:** один процесс-писатель (`flock(LOCK_EX)` сохраняется, повторный экземпляр → `Busy`), N потоков-writer'ов, один координатор group commit, один GC; потоки взаимно доверенные. Изоляция зон — производительная, не security (RR-9); межзонная атомарность не предоставляется (RR-8). Несколько процессов-писателей — **v3**, отдельный ADR (file-side seqlock/история голов, byte-range leases); до этого запрещены.
- Часы хоста синхронизированы (влияет на TSIG fudge и DNSSEC validity); дрейф обрабатывается как ошибка, не как успех.
- v1 поставляется двумя бинарниками: `pulsed` (authoritative) и `pulseresolved` (recursive); рекурсия закрыта по умолчанию (доверенные сети/ACL).
- client IP и qname не пишутся в логи по умолчанию; только агрегированные метрики.
- DNS rebinding protection не реализуется в v1 (RR-7); при рекурсии на недоверенном интерфейсе — warning в конфиг/лог и документация.
- **Модель — single-tenant:** один оператор на инстанс; мультитенантность и изоляция по tenant — вне scope v1.
- **Развёртывание — single-host:** репликация только штатная DNS (AXFR/IXFR/NOTIFY); сетевое FS и консенсус — вне scope.

## 10. Открытые вопросы к пользователю

**Все вопросы закрыты:** оба бинарника, рекурсия закрыта по умолчанию; DoT/DoH — M6; DNSSEC-алгоритмы (RSA/SHA-256 обязателен); HSM — не в v1; 0x20 — по умолчанию; приватность — без client IP/qname в логах; rebinding — вне v1, warning/docs (RR-7); **multi-tenancy — нет (single-tenant)**; **кластер — нет (single-host, только DNS-репликация)**; blocklist — `https`+allowlist+64 MiB+no redirects, подпись — roadmap; калибровка лимитов — M3; M4 gate — `SEC-RES-013`.

**Открытых вопросов по базовому режиму нет.** Открытые вопросы параллельного режима (ADR-0006 §13, ADR-0004 §15) — разрядность `version` в пине, `MAX_PINNED_ZONES`, `MAX_LEAK_RATIO`, `freeze()` в v2.0, chain-GC-тюнинг, синхронизация `domain-model`, M3-ADR для N процессов — не блокируют M1; **M3 блокирован** до ADR по F-5.
